# azn brbr — prototype

Working prototype of the feed + flagship profile pages from
`asian-hair-barber-app-spec.md`, built to gut-check whether the vouch/split-score/
personalization concept actually reads well on screen before investing in real
backend infra.

## Running it

```
npm install
npm run dev
```

Then open http://localhost:3000 — it redirects to `/city/seattle` (richest seed
data). Use the city dropdown in the nav to switch cities, and "Your home
barber" to switch personas and see the "vouched for by your barber" banner
light up differently per profile (try setting it to **Maison de MI Salon**,
then visiting the **Falali Hair Salon** profile in Seattle).

This was scaffolded in a sandboxed environment with no npm registry access, so
`npm install` / `npm run dev` have **not been run or verified** from this side.
The code was written and manually reviewed for correctness, but you're the
first one to actually boot it — expect the normal first-run rough edges.

## Design

Desktop-first. Cream paper (`#F7F3EC`), deep forest (`#1E3A32`), one clay accent
(`#8C3A28`) reserved for cautions and the personalization signal — so when
either appears, it means something. Fraunces for display, Inter for UI, loaded
via `next/font`. Rows are hairline-separated rather than floating cards, and
shops are represented by typographic monograms (deterministic colour per shop)
rather than stock photography we don't have.

Screens: `/` landing (world map + filters) → `/city/[slug]` results (list + map
split) → `/barber/[id]` profile.

## Tag taxonomy

"Asian hair" is **not** a tag — it's the product's baseline, so it would apply
to every row and distinguish nothing. Tags split into:

- **Hair types** (what the discovery filter asks): Fine & straight, Thick &
  straight, Coarse & dense, Wavy, Curly, Cowlicks & crowns.
- **Services**: Fades & tapers, Perms, Straightening & rebonding, Colour,
  Kids cuts.

Caveat: the seed research overwhelmingly produces `Thick & straight` (43 of 51
vouched shops), because most source reviews say some version of "knows Asian
hair" without describing texture. That's a limitation of review-derived data,
not a real distribution — the other textures will only populate properly once
real people vouch and say what their hair is actually like.

## What's real vs. mocked

- **Seed businesses are real** — pulled from the companion spreadsheet
  (`asian_hair_barber_seed_list.xlsx`), which itself came from Google Places
  data + community-thread research (see the spec's "Discovery data strategy").
- **Vouches are synthetic.** No real customer has used this app yet. The
  `vouches` in `data/seed.json` are paraphrased dramatizations of the seed
  spreadsheet's "Signal notes" column, generated by `scripts/build_seed.py`,
  so the feed/profile pages have realistic-looking content to design against.
  Treat this as placeholder content, not real user data — see the docstring
  at the top of that script.
- **The city map is a placeholder.** No live map provider is wired up yet
  (locked decision: Google Maps JS). City-page pins are positioned
  deterministically from the shop id, **not geocoded** — enough to demonstrate
  the list ↔ docked-card interaction, not for navigation. Labelled as such
  on screen.
- **The landing world map IS real coordinates.** Cities are plotted by actual
  lat/long on an equirectangular projection; the dot-grid landmass behind them
  is a coarse approximation (`lib/worldmap.js`) and decorative only.
- **Budget filter is inert by design.** No price data exists in the seed set —
  see the spec's Discovery flow section.

## Cities

Eleven so far, in `data/seed.json` / `asian_hair_barber_seed_list.xlsx`:

- Original six (Google Places + community search): NYC, Chicago, Seattle,
  Paris, Lisbon, Berlin.
- Five more (web-search-only research — see caveat below): London, Sydney,
  Toronto, Amsterdam, Madrid. Chosen for a strong Asian population and/or
  Asian travel draw. Signal quality varies a lot: Sydney and London turned up
  solid, specific leads (including two good tag-scoped-caution examples —
  DNK Hair and Kim Sun Young in Sydney, both praised for cuts but flagged on
  perm/straightening specifically); Toronto and Madrid came back thin despite
  large Asian populations, mirroring the original NYC finding — the knowledge
  likely exists locally but isn't showing up in searchable English text yet,
  meaning manual outreach will matter most there.

**Caveat on the 5 newer cities:** researched via web search only (no Google
Places API access from this environment), so address/rating/review-count
fields are only filled in where a search snippet actually surfaced them —
nothing was invented. `Source` column in the spreadsheet says "Web search"
rather than "Google Places" for these rows so the provenance stays visible.
Worth a real Places-API pass before treating this as seed-complete the way
the original six are.

## Locked decisions this build assumes

From the spec's open questions, resolved before this build started:

1. Operator-to-operator cautions: customer-only for now.
2. Unconfirmed Places listings: separate "help us confirm" section, not mixed
   into the main feed.
3. Operator-vouch threshold: left as a placeholder (not load-bearing in a
   static prototype with no real gating logic).
4. Map provider: Google Maps JS, once a real map is wired up.
5. Docked map card: minimal (name + top-tag score + link to full profile).
6. Simplified vs. Traditional Chinese: deferred along with site-wide language
   switching generally.

## Structure

```
app/                    Next.js app router pages
  layout.js             root layout, wraps everything in HomeBarberProvider + nav
  page.js                redirects to /city/seattle
  city/[citySlug]/       feed page (list + map placeholder + unconfirmed section)
  barber/[id]/           flagship profile page
components/              all UI pieces, mostly client components (need interactivity/context)
lib/data.js              seed-data query helpers (split score, languages, home-barber-vouch lookup)
data/seed.json           generated — do not hand-edit, edit the xlsx + rerun scripts/build_seed.py
scripts/build_seed.py    xlsx -> seed.json, with mock vouch generation
scripts/append_new_cities.py   added the 5 newer city tabs to the xlsx
```
